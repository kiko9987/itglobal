# 방문 일정 매니저 가이드

방문 lead 등록 → 매니저 배분 → 방문 처리까지 슬랙 flow 안내. 매니저 시점.

_최종 업데이트: 2026-07-27_

---

## 1. 전체 흐름

```
[방문 요청 등록]                 [자동 정리]              [매니저 배분]
슬랙 워크플로 or 온라인 리드  →  #방문_일정 카드    →   JW 두번째 캔버스 정리
                                 첫번째 캔버스 자동                ↓
                                                            /일정확정 명령
                                                                  ↓
                                                        List 담당자 자동 반영
                                                              + DM 발송
                                                                  ↓
                                                              [매니저 방문]
                                                                  ↓
                                                    [정보 수정] / [방문 완료] / [방문 취소]
```

## 2. 방문 요청 등록

### 온라인 lead (홈페이지·당근·카카오톡)
- 자동 유입 → 시트 등록 + `#온라인_문의` 카드 발송 → 매니저 [상담하기] → 방문 예약 확정
- 주소는 자동 정규화됨 (원본 vs 변환 주소 카드에 표시)

### 거래처·기타·소개
- 슬랙 워크플로 **"방문요청 등록하기"** 로 시트에 직접 등록
- 10초 안에 `#방문_일정` 채널 카드 발송 + 슬랙 List 등록

### 주소 자동 정규화 (거래처·기타·소개·전화, 2026-07-20 도입 / 2026-07-22 UI 개편)

매니저가 raw 주소 (예: 거래처가 준 원본) 를 그대로 붙여넣으면 카카오·네이버 API 로 자동 정정합니다.

**방문 카드 본문에 원본/변환 두 줄 대조** (온라인 lead 카드와 동일 스타일):

- **정규화 성공 & 원본 ≠ 변환**
  ```
  >*원본 주소* : 강남대로 213 엘타워 지하 1층 방재실
  >*변환 주소* : `서초구 `강남대로 213 엘타워 지하 1층 방재실
  ```
  - 변경된 부분은 인라인 강조로 표시 (규칙은 아래 참조)
- **카카오 인식 실패** → `>방문 주소 : ...  :warning: *[주소 확인 필요]*` — 원본 유지, `[✏️ 정보 수정]` 로 재입력
- **원본 = 변환** → 단일 줄 `>방문 주소 : ...` (배지 없음)
- **주소 미입력** (고객이 폼 주소란을 안 채움) → `>방문 주소 : 주소 미입력` (2026-07-27)
  - 빈 값·`()`(빈 괄호)·구두점만 남는 경우 모두 `주소 미입력` 으로 통일 표기
  - 인입 카드·방문 카드·취소 카드 공통. 방문 전 전화로 주소 확인 후 `[✏️ 정보 수정]` 으로 입력

### 특이사항 자동 이동 (2026-07-24)

매니저가 워크플로 **방문 주소** 필드에 개행 후 특이사항 (`방문 전 연락 요망`,
`인테리어 중` 등) 을 함께 입력하면:

- **첫 줄** = 실제 주소 (카카오 정규화 대상)
- **2번째 줄+** = 자동으로 상담 내용 (K열) 뒤에 ` / ` 로 구분해 append
- 등록자에게만 보이는 **ephemeral 안내** 방문 채널에 발송 (다른 매니저 노출 X)

> 자동 분리는 **개행 있는 케이스만** 감지합니다. 한 줄로 붙여쓰면 (예: `... 11층 방문 전 연락`)
> 카카오 정규화가 어긋날 수 있으므로 **주소 필드에는 주소만, 특이사항은 상담 내용 필드에** 입력하는 것이 정확합니다.

**Diff 강조 규칙** (자모 오탈자·건물명 변경 즉시 인지):
| 청크 길이 | 스타일 | 예시 |
|-----------|--------|------|
| 1자 | 홑따옴표 `'X'` | `판교제2테크노'벨'리` → `'밸'` |
| 2자+ | 볼드 `*X*` (Word Joiner 삽입으로 한글 사이에서도 렌더) | `KBS*아레나*` → `*스포츠월드*` |
| 5개 초과 | 하이라이트 스킵 (두 줄 raw 대조만) | 오탈자·공백·괄호 여러 곳 동시 정정 시 노이즈 방지 |

등록자 본인에게는 별도로 **채널 ephemeral 알림** (본인만 보임) 이 함께 발송됩니다.

> **팁**: 카카오와 네이버는 결과가 다를 수 있습니다 (건물명·지점명·호수 등). 카카오가 이상하게 잡으면 네이버 검색으로 확인 후 [정보 수정] 으로 정정하세요.
> `X캠퍼스 Y캠퍼스` 처럼 같은 접미어가 인접해 오면 카카오 표준(앞) 유지, 통칭(뒤) 자동 제거됩니다 (예: `고려대학교 서울캠퍼스 안암캠퍼스` → `서울캠퍼스`).

## 3. 매니저 배분 (JW 담당)

두 개의 캔버스:
- **첫번째 (자동 생성)**: `방문 일정 스케줄` — 봇이 시트에서 방문 예약 lead 를 자동 정리
- **두번째 (JW 수동)**: `방문 일정 스케줄 (JW 전용)` — JW 가 매니저별로 배분 정리

### 표준 양식 (두번째 캔버스)
```
방문 일정 스케줄 (JW 전용)

MJ                              ← 개인 담당자 섹션
  MJ * 2026-07-20 / 010-... / 주소 / 상담내용
  대표님 + TH * 2026-07-21 / ...  ← 이니셜 조합 배정

... 다른 담당자 섹션

온라인                          ← 특수 섹션
JK                              ← 그날 사무실 상담 당번
SD(오전)+MS(오후)               ← 시간대별 담당 (2026-07-21 지원)

휴무                            ← 특수 섹션
휴무인원 ( JSH + YM + SJ )      ← 괄호 안 = 휴무자
```

### 파싱 규칙
- 이니셜 조합 구분자: `+`, `,`, `·`, `/`, `*` 모두 인식
- 별명: `대표님 → YG`, `정우 → JW`
- **온라인**: 그 아래 이니셜 = 상담 당번 (방문 DM 대상 X)
  - 시간대 표기 지원 (`SD(오전)+MS(오후)`) — 이니셜별 shift 정보 v13 DM 에 반영
- **휴무**: 괄호 안 이니셜 = 그날 휴무자 (온라인 당번 DM 하단에 표시)

### 슬래시 명령

| 명령 | 동작 | 권한 |
|------|------|------|
| `/일정확인` | dry-run — 파싱 결과만 미리보기 (시트·List·DM 안 건드림) | JW·YG·KiKO |
| `/일정확정` | commit — 시트 영업 담당자 update + List 담당자 반영 + DM 발송 | JW·YG·KiKO |

**flow**: 캔버스 정리 → `/일정확인` 으로 검토 → 이상 없으면 `/일정확정` → 자동 발송

### 발송 DM 종류

| ID | 대상 | 내용 |
|----|------|------|
| v9 | 배정된 매니저 | 다음 날 방문 일정 (담당 현장 목록 + 동행 인원) |
| v13 | 온라인 당번 | 상담 당번 안내 + 방문 참고 정보 + 휴무자 정보 |
| v19 | 방문 담당 매니저 | 방문 일정 변경 시 (`정보 수정` 사용된 경우) |
| v20 | 이전 담당 매니저 | 재배정 시 "변경된 현장 배정 안내" |
| v21 | 방문 담당 매니저 | 방문 취소 알림 (사유 포함) |

### 재배정 안내 (v20, 2026-07-19 도입)
- 이전에 배정됐던 매니저가 다시 `/일정확정` 시점에 다른 매니저로 바뀌면, 이전 매니저에게 "변경된 현장 배정 안내" DM
- **어감**: 노는 사람은 없음. 배정이 바뀌는 건 다른 현장 갔기 때문 — "제외" 가 아니라 "재배정" 뉘앙스
- 문구: `🔄 {매니저}님, {날짜} 방문 {N}건이 다른 매니저에게 재배정되었습니다.`

### v9 재발송 정책 (2026-07-27 개편)

일정 확정 후 캔버스 수정 → 재확정 시 매니저 DM 이 왕복되며 헷갈리는 문제 해결. **매니저별 v9 = "지금 배정의 최신 진실"** 원칙.

| 상황 | 동작 |
|------|------|
| 신규 매니저 (첫 확정) | v9 발송 (헤더 없음) |
| **배정 동일** (순서 무관) | **skip** — 기존 v9 그대로 유지, 알림 없음 |
| **배정 변경** (+추가/-제거/양쪽) | 기존 v9 **삭제** + 상단에 `🔄 일정 업데이트 (N건 → M건)` 헤더 붙여 재발송 (총 건수 반영) |
| **완전 제거** (배정 취소) | 기존 v9 **삭제** + v20 재배정 안내 (`기존 배정 안내 DM 은 삭제되었습니다.` 라인 포함) |

**핵심**: 매니저 폰에는 항상 최신 v9 하나만 남음. 이전 v9 는 삭제되므로 "몇 건이었지?" 헷갈림 X. 순서만 다른 재확정은 skip 이라 재알림 없음.

**Redis key**: `dm_v9_msg:{ini}:{date}` = `{channel, ts, lead_nos}` TTL 7일

## 4. 방문 카드 액션 (`#방문_일정`)

카드 하단 3개 버튼:

### [✏️ 정보 수정]
- 방문 날짜·주소·상담 내용 조정
- **하루~일주일 미루기** 는 여기서 처리 (취소 아님)
- 방문 예정일 변경 시 v19 알림 발송

### [✅ 방문 완료]
- 완료 처리 → 슬랙 List 에서 삭제
- 확인 팝업 있음

### [🗑️ 방문 취소] (2026-07-19 개편)
- **사유 입력 모달** 이 뜸 (예: "타업체 공사 진행", "다음달로 방문 연기 요청")
- 제출 시:
  - 상담 내용에 사유 append
  - 시트 상태 → `방문 취소`
  - v21 알림 DM (담당 매니저에게)

**취소 vs 정보 수정 사용 기준**:
- 하루~일주일 미루기 → **[정보 수정]** 으로 방문 날짜만 조정
- 한 달 뒤 or 완전 취소 → **[방문 취소]** + 사유 입력

## 4.5. 부재중 / 미완료 리마인드 (매일 09시 자동, 2026-07-23 도입)

어제 인입된 문의 중 오늘 재시도가 필요한 건을 매일 아침 9시 온라인 문의 채널에 요약 카드로 발송합니다.

### 대상 조건

| 섹션 | 조건 | 수집 범위 |
|------|------|-----------|
| 🗨️ **미완료** | 상태 = `상담 대기` & 온라인 상담자 미배정 (매니저가 아예 못 열어본 것) | 직전 영업일~어제 인입분 |
| 📞 **부재중** | 상태 = `부재중` & 영업 담당자 없음 (콜백했으나 미연결) — 매니저별 그룹 | 직전 영업일~어제 인입분 |
| 🧾 **견적 요청 (미제출)** | 상태 = `견적 요청` (아직 견적 제출 전) — 등록자(온라인 상담자)별 그룹 | **날짜 무관 전체** — 제출·방문예약·드랍 전까지 매일 (2026-07-27) |

- **견적 요청** 은 며칠 걸릴 수 있어 다른 항목과 달리 **날짜 스코프 없이** 상태가 `견적 요청` 인 동안 매일 표시. 상태가 `견적 제출`·`방문 예약`·`문의 드랍` 등으로 바뀌면 자동 이탈. 접수일(`07.27(월) 18:31`)을 병기해 대기 기간 파악.

### 카드 예시

```
:bell: *어제 미처리 문의 (5건) — 오늘 다시 연락 부탁드립니다*
--------------------------------------------
:speech_balloon: *미완료 (3건)*
• `L-03335` [카카오톡] 아보카도 932 · 어제 17:02  |  <확인하기>

:phone: *강민석 (MS) 부재중 (1건)*
• `L-03324` [당근] 홍란 · 010-5386-2489  |  <확인하기>

:receipt: *고광일 (KiKO) 견적 요청 (미제출) (1건)*
• `L-03411` [전화] 반포 자이 · 07.27(월) 18:31  |  <확인하기>
--------------------------------------------
:information_source: 부재중 2번 이상일 시 문의 드랍 처리 해주세요.
:information_source: 견적 요청은 견적 제출·방문 예약·드랍 처리 전까지 매일 표시됩니다.
```

- **확인하기** 링크 → 원본 lead 슬랙 카드로 바로 이동
- 대상 0건이면 카드 발송 안 됨 (조용한 아침). 견적 요청만 있어도 발송됨.
- 스케줄러 job id: `absent_remind_daily` (변경 필요 시 `dashboard/services/sync_scheduler.py`)

## 4.6. 상담 완료 처리 · 카드 UX 정책 (온라인 문의 채널, 2026-07-23 개편)

온라인 문의 카드에서 매니저가 [상담하기]·[재상담] 클릭 → 상담 모달 제출 시 상태별 카드·댓글 처리. 모든 헤더는 통일된 라벨 (`처리자` / `처리 시간` / `상담 내용` — 취소는 `취소자` / `취소 시간` / `취소 사유`) 을 사용.

| 상태 | 원본 카드 | 헤더 (lead_no 포함) | Thread Reply | 재클릭 진입점 |
|------|----------|---------------------|--------------|---------------|
| **방문 예약** | 회색 처리 | `✅ *상담 완료 - 방문 예약*  ` + `L-XXXXX` | ✅ **permalink 링크 1개** (`#방문_일정 카드에서 상세 보기` — Slack unfurl 로 방문 카드 preview) | 방문_일정 카드 [정보 수정] |
| **유선 상담** | 회색 처리 | `✅ *상담 완료 - 유선 상담*  ` + `L-XXXXX` | ❌ 없음 | 회색 카드 [✏️ 재상담] |
| **견적 제출** | 회색 처리 | `✅ *상담 완료 - 견적 제출*  ` + `L-XXXXX` | ❌ 없음 | 회색 카드 [재상담] |
| **문의 드랍** | 회색 처리 | `✅ *상담 완료 - 문의 드랍*  ` + `L-XXXXX` | ❌ 없음 | 회색 카드 [재상담] |
| **부재중** | **원본 body 유지** (재시도 시 문의 내용·주소 참고 필수) + 상단 section 배지 | `🔄 *부재중* (총 N회)` — lead_no 는 원본 body 상단에 이미 있어 중복 회피 | ❌ 없음 | 원본 카드 [상담하기] 그대로 |
| **방문 취소** (방문_일정 채널 별도 flow) | 회색 처리 | `🚫 *방문 취소*  ` + `L-XXXXX` | ❌ 없음 | 회색 카드 [↩️ 취소 되돌리기] |

### 방문 예약 permalink reply 예시
```
✅ *방문 예약 등록* — `L-XXXXX` by `MS`
📍 <#방문_일정 카드에서 상세 보기>
```
- Slack unfurl 로 방문 카드 preview 자동 렌더
- 재제출 시 옛 reply 삭제 + 새로 발송 (unfurl 재생성)
- **전화 workflow 자동 등록도 동일 형식** (`sync_workflow_phone_leads`)

### 전화 문의 수동 입력 — 상태별 카드 (`sync_workflow_phone_leads`)

슬랙 워크플로 **"전화 문의 수동 입력"** 의 `상담 유형` 은 매니저 통화 후 결과를 기록하는 값이라, 대부분 **회색 완료 카드** (`✅ 상담 완료 - {상태}` + `[재상담]`) 로 발송됩니다. 예외 2가지:

| 상담 유형 (시트 D열) | 카드 | 의미 |
|----------------------|------|------|
| **견적 요청** (2026-07-27 신설) | 🔔 **활성 인입 카드 + `[상담하기]`** (회색 X) | "가견적만 달라"는 요청 접수 — **아직 상담 전**. 온라인 새 리드처럼 담당 매니저가 견적 준비 후 `[상담하기]` 로 처리 |
| **부재중** | 원본 body 유지 + 상단 배지 | 위 §4.6 부재중 정책과 동일 |
| 유선 상담·방문 예약·**견적 제출**·문의 드랍 | 회색 완료 카드 | 통화 완료 후 결과 기록 |

- **견적 요청 vs 견적 제출**: `견적 요청` = 상담 전 (활성) / `견적 제출` = 상담 후 결과 (회색 완료). 헷갈리지 말 것.
- 견적 요청 카드도 `build_inquiry_blocks` 재사용 → 온라인 리드와 100% 동일 UX·`button_consult` action. `lead_card_msg` 저장되어 이후 [상담하기]·재문의 연결 정상 동작.

### 부재중 배지 3줄 구조
```
🔄 *부재중* (총 *N회*)
처리자 : SD
처리 시간 : 07.22 17:35
상담 내용 : 전화 안받음
```
- 재클릭 시 배지만 갈아끼우기 (context/section 둘 다 감지)
- 원본 body 그대로 노출되므로 lead_no 는 body 상단에 이미 있음 → 배지에는 중복 회피

### 검색·이력 확인
- 원본 카드 회색 헤더 (`✅ 상담 완료 - {상태}  L-XXXXX`) 로 검색 — 상태 + lead_no 동시 검색 가능
- 부재중은 원본 body + 상단 배지 (`🔄 부재중`) 로 검색
- 매니저·시간·사유 모두 헤더에 포함 → thread reply 없어도 충분

### 개편 배경
같은 lead 가 원본 카드 + 상세 reply 로 두 번 검색 결과에 뜨는 노이즈 제거. 방문 예약만 방문_일정 채널 카드와 연결 필요해 짧은 링크 유지. 헤더 라벨·lead_no 통일로 매니저가 어떤 상태 카드에서도 동일 위치에서 정보 확인 가능.

### 스레드 텍스트 자동 감지 (2026-07-26 도입)

`[상담하기]` 모달을 열지 않아도 스레드에 지정된 키워드만 남기면 시스템이 자동으로 상태를 갱신합니다. 부재중 처리를 스레드로만 남기고 모달을 안 눌러 시트가 미갱신 상태로 남던 사고 방지용.

#### 지원 키워드 (정확 매치, 20자 이하 단일 라인만)

| 결과 상태 | 인식되는 텍스트 |
|-----------|------------------|
| **부재중** | `부재중`, `부재`, `전화 안받음`, `전화안받음`, `안 받음`, `안받음`, `노쇼`, `no show` |
| **문의 드랍** | `드랍`, `문의 드랍`, `문의드랍`, `드랍 처리`, `드랍처리` |

문장부호 (`.`, `!`, `~`, `,`) 는 자동으로 허용됩니다 (`부재중.`, `드랍!` OK).

#### 처리 결과
- **시트**: 상태 갱신 + 온라인 상담자에 본인 이름 기록 + 상담 내용 K열에 `[MM.DD HH:MM 이니셜 · <상태>] <원문>` 마커 append
- **부재중**: 카드 원본 body 유지 + 상단 배지 (기존 부재중 정책과 동일 양식, 회차 카운트 증가)
- **문의 드랍**: 카드 회색 완료 처리 + `[✏️ 재상담]` 버튼
- **스레드 답글**: `:white_check_mark:` reaction 부착 (알림 없음)

#### 오탐 방지
- **채널 제한**: 온라인 문의 채널 (`SLACK_LEAD_CHANNEL`) 전용. 다른 채널 무영향
- **길이 제한**: 20자 초과 or 여러 줄 텍스트는 무시 (`이거 부재중 처리해줘야 될 듯` 같은 자연어 skip)
- **정확 매치**: `부재중이었어요` 처럼 조사 붙은 형태도 skip. 단순 키워드만 반응
- **이미 완료된 lead**: `상태 != 상담 대기` 인 경우 ephemeral 안내 후 skip (부재중만 재시도 허용 — 카운트 증가)
- **중복 이벤트**: Redis dedup (`auto_thread_status:{event_ts}` TTL 10분)

#### 실수 시 대응
1. 원문에 `이 스레드 실수로 남긴 텍스트입니다` 같은 다른 답글을 남겨도 자동 처리는 이미 완료된 상태
2. 웹 대시보드에서 lead 검색 → 상태 수동 정정
3. 카드 회색화는 남아있으므로, 재상담 필요 시 `[✏️ 재상담]` 버튼으로 정상 flow 복원

## 5. 사진 첨부 · 폴더 저장

방문 후 카드 스레드에 사진을 첨부하면 봇이 자동으로:
1. Google Drive 에 폴더 생성 → 사진 업로드
2. 카드 자동 [방문 완료] 처리
3. 스레드에 폴더 링크·경로·ID 답글 발송

### 투 트랙 정책 (2026-07-24) — 외부 LTE 환경 대응

외부 LTE 에서 사진 대량 첨부 시 슬랙 업로드 실패가 잦음 (카톡 30장 vs 슬랙 10장 제한, 역체감). 매니저 협의:

- **10장 미만**: 기존대로 현장에서 스레드에 첨부 → 폴더·업로드·자동 완료 한 번에 처리
- **10장 이상**: 사무실 복귀 후 와이파이 환경에서 첨부. 대신 **현장에서는 [✅ 방문 완료] 버튼만 눌러도 폴더가 생성**됨

**동작**:
- 완료 버튼 시 폴더 사전 생성 → 스레드에 `📁 방문 폴더 생성됨: <링크>` 안내 reply
- 사무실 복귀 후 사진 첨부 시 **folder_id 기반으로 그 폴더에 저장** (이름 재계산 X)
- 폴더명 정정 필요 시 (예: `SB+MJ 동행` 배정이었으나 SB 혼자 방문) Drive 에서 이름 바꿔도 무관 — folder_id 로 연결

### 폴더명 형식
`{플랫폼} ({이니셜}) {방문 주소} {YY.MM.DD}`

예: `당근 (MJ) 김포 김포한강9로115번길 20-10 취연빌 101호 26.07.18`

- **플랫폼 prefix**: 광고 플랫폼 (당근/거래처/숨고/기타 등) 만 붙음. 홈페이지·전화·카카오톡·채널톡 은 prefix 없음.

### 이니셜 결정 규칙 (2026-07-20 개선, 2026-07-24 완료 버튼 트리거에도 적용)

**거래처 / 기타 / 소개**: **등록자** (M열 = 워크플로 시작자) 우선
- 대표님이 등록하고 매니저를 대신 보낸 경우도 폴더는 **등록자 이니셜** (관리 주체 개념)
- "본인 방문 필수" 체크 시엔 M=N 자동 복사되므로 무관

**온라인** (홈페이지/당근/카카오톡/전화/채널톡): **방문 담당자** (N열) 우선
- N열 없으면 → **사진 업로더 or 완료 버튼 누른 사람** (당일 즉시 방문 케이스 대응)
  - 예: JK 상담 후 근처 MJ 가 즉시 방문 → List 배정 없이 MJ 가 사진 올리면 폴더 `(MJ)` 로 생성
- 그것도 실패 → M열 (온라인 상담자) fallback

**⚠️ 예외 케이스**: 온라인 미배정 상황에서 A 가 방문하고 B 가 대신 완료 버튼 누르면 폴더 `(B)` 로 잘못 생성. Drive 에서 이름 정정하면 사후 첨부는 정상 (folder_id 재사용).

### 추가 기능
- **상호명 추가**: 스레드에 `상호 OOO` 답글 → 폴더명 뒤에 상호명 자동 부착
- **위치 분류**: 사진 첨부 시 캡션에 `1층`, `2층 휴게실` 등 위치 입력 → 서브폴더 자동 생성
- **10장씩 나눠 올려야** 함 (슬랙 UI 제약, 같은 폴더에 이어서 저장)
- **폴더 삭제·이동**: Drive 에서 폴더 삭제·이동된 상태에서 사후 첨부 시 → folder_id 조회 실패 감지 → 자동으로 신규 폴더 생성 fallback (사진 손실 없음)

## 6. FAQ / 팁

**Q. 주소 배지가 이상하게 잡혔어요.**
카카오 API 결과가 완벽하지 않은 경우가 있습니다. [정보 수정] 으로 정확한 값 재입력하세요. 시트·카드·슬랙 List·캔버스 모두 자동 반영됩니다.

**Q. `/일정확정` 실수로 눌렀어요.**
이미 DM 발송된 건은 회수 불가. 다시 캔버스 수정 후 `/일정확정` 을 하면 diff (신규/유지/제거) 를 자동 계산해서 필요한 알림만 재발송합니다.

**Q. 취소 사유 뭐라고 써야 해요?**
간단하고 구체적으로. 예:
- 타업체 공사 진행
- 다음달로 방문 연기 요청
- 고객 연락 두절
- 방문 시 부재중 (재방문 불가)

**Q. 캔버스 파싱이 안 돼요.**
표준 양식 (섹션 2) 을 정확히 지키세요. 특히 "온라인", "휴무" 는 특수 헤더로 인식됩니다. 이니셜은 반드시 users.db 등록 이니셜 (이메일 로컬 파트 대문자) 이어야 합니다.
