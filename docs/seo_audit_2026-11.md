## 1. 지금 당장 고칠 것

### ① 사이트맵에 홈(`/`)이 없고, 홈과 똑같은 `/index` 가 대신 올라가 있다

가장 영향이 크다. 홈이 사이트맵에 없고, 내용이 글자 하나까지 같은 `/index` 가 그 자리에 있다.

실측:

```
$ curl -s https://www.itg-aircon.com/sitemap.xml
  /construction-case  /cleaning  /event  /review  /index      ← 5개. '/' 가 없다
```

| | `/` | `/index` |
|---|---|---|
| 응답 | 200 | 200 |
| canonical | `https://www.itg-aircon.com/` | `https://www.itg-aircon.com/index` |
| title | 상업용 냉난방기 · 시스템에어컨 전문 \| (주)아이티글로벌 | **같음** |
| description | LG·삼성·캐리어 인증 전문점… | **같음** |
| H1 | 상업공간을 위한 냉난방 솔루션의 기준을 만듭니다. | **같음** |
| HTML 크기 | 1,167,030 바이트 | 1,167,029 바이트 |

두 주소가 각자 자기를 canonical 로 선언한다. 즉 **구글에게 "서로 다른 두 페이지"라고 말하면서 내용은 같다.**
게다가 사이트맵은 `/index` 만 제출하고, 모든 페이지의 메뉴 '홈' 링크도 `/index` 로 걸려 있다(아래 내부 링크 표).
그래서 링크·사이트맵은 `/index` 를 밀고, 사람들이 아는 주소는 `/` 다. 둘로 갈린다.

**아임웹 어디에서**
1. 메뉴 설정에서 '홈' 메뉴의 링크를 `/index` 가 아니라 사이트 첫 페이지(`/`)로 바꾼다.
2. 그다음 `/index` 페이지의 메뉴 설정에서 「이 페이지 검색엔진 차단」을 켠다. 그러면 아임웹이 noindex 를 붙이고 사이트맵에서도 빠진다.
3. 사이트맵에 `/` 가 들어오는지 하루 뒤 `https://www.itg-aircon.com/sitemap.xml` 로 확인한다.

**왜** 홈은 보통 가장 강한 페이지다. 그 힘이 `/index` 와 반으로 갈리고, 사이트맵은 홈을 아예 제출하지 않는다.

> 순서가 중요하다. 메뉴 링크를 먼저 `/` 로 바꾸지 않고 `/index` 를 차단하면, 모든 페이지의 '홈' 버튼이 차단된 페이지로 가게 된다.

---

#### ⛔ 위 처방 2번(`/index` 검색엔진 차단)은 하면 안 된다 (2026-11-17 재실측, 정정)

`/index` 를 차단하면 **홈(`/`)까지 같이 검색에서 빠진다.** 둘은 다른 페이지가 아니라 같은 한 페이지다.

실측 — 두 주소가 다른 것은 요청 주소를 그대로 적는 칸(canonical·OG URL)뿐이다:

| | `/` | `/index` |
|---|---|---|
| title | 상업용 냉난방기 · 시스템에어컨 전문 \| (주)아이티글로벌 | **같음** |
| description | 같음 | **같음** |
| `robots` 메타 | 없음 | **없음** (양쪽 따옴표로 다시 셌다) |
| 크기 | 1,167,046 바이트 | 1,167,076 바이트 (canonical·OG 에 "index" 다섯 글자가 더 붙은 만큼) |
| canonical | `…/` | `…/index` |

제목·설명이 한 글자도 다르지 않다. **아임웹의 페이지 설정은 페이지 단위로 하나뿐이라는 뜻이고,
'이 페이지 검색엔진 차단' 도 같은 설정 칸이다.** 켜면 `/` 로 들어와도 `noindex` 가 붙는다.

게다가 아임웹 자동 사이트맵이 홈을 `/index` 로 내보낸다. 즉 **아임웹이 보는 홈의 정식 주소가 `/index`** 다.
우리가 끼어들 자리가 아니다.

#### 그러면 무엇을 하나 — 먼저 확인할 것 두 가지

부장님만 볼 수 있는 화면이다. 둘 다 보고 알려 주시면 그다음 조치를 정한다.

1. **디자인 모드 → ≡ → '홈' 메뉴 → ⋮ → 설정** 에서 **주소(URL) 칸이 `index` 로 되어 있는지**, 비울 수 있는지.
   비울 수 있으면 그것만으로 끝난다 — 메뉴 링크와 사이트맵이 `/` 가 된다.
2. **설정 → SEO** 의 **사이트맵이 자동 생성인지, 직접 입력 칸이 있는지.**
   직접 입력이면 `/index` 를 `/` 로 바꿔 넣으면 된다.

둘 다 안 되면 남는 길은 헤더 코드 자바스크립트로 `href="/index"` 를 `/` 로 갈아 끼우는 것인데,
사이트 전체 내비게이션을 건드리는 일이라 **설정으로 되는지 먼저 확인한 뒤에 판단한다.**

내부 링크 실측 — 살아 있는 5페이지 전부 `href="/index"` 가 6개씩이다(PC·모바일 메뉴).

```
/                   href=/index 6개 · href=/ 1개
/cleaning           href=/index 6개 · href=/ 0개
/review             href=/index 6개 · href=/ 0개
/event              href=/index 6개 · href=/ 0개
/construction-case  href=/index 6개 · href=/ 0개
```

#### 얼마나 급한가

**급하지 않다.** 두 주소가 각자 자기를 canonical 로 선언하지만 내용이 같으니 구글은 둘 중 하나를 골라 색인한다.
외부 링크와 브랜드 검색이 `/` 로 몰리므로 구글이 `/` 를 고를 가능성이 높다.
최악은 검색 결과에 홈 주소가 `/index` 로 나오는 것이고, 그래도 페이지는 제대로 열린다.
**잘못 건드려 홈이 `noindex` 되는 쪽이 훨씬 큰 손해다.**

### ② FAQ 가 없는 4개 페이지에도 FAQ 구조화 데이터가 붙어 있다

FAQ 스키마를 아임웹 **헤더 코드(head)** 에 넣었는데, 헤더 코드는 모든 페이지에 들어간다.
그래서 FAQ 섹션이 화면에 없는 페이지에도 질문 8개가 그대로 붙었다.

실측 — 페이지별 JSON-LD 종류:

```
/                   graph[Organization+HVACBusiness, WebSite] / FAQPage / Organization / ImageObject
/cleaning           graph[...] / FAQPage / Organization            ← FAQ 섹션 없음
/construction-case  graph[...] / FAQPage / Organization            ← FAQ 섹션 없음
/review             graph[...] / FAQPage / Organization            ← FAQ 섹션 없음
/event              graph[...] / FAQPage / Organization / ImageObject ×2  ← FAQ 섹션 없음
/index              graph[...] / FAQPage / Organization / ImageObject
```

우리 쪽 문서(`docs/imweb_faq_schema.html`) 첫 줄에 이미 적혀 있는 규칙을 우리가 어긴 상태다.

> ⚠️ 규칙: 여기 내용 = 화면에 보이는 FAQ 와 같아야 함(구글 지침)

**아임웹 어디에서** 사이트 설정 → SEO·헤더 설정 → 헤더 코드.
지금 FAQ 스키마는 `<!-- END HEADER -->` 뒤에 `<script type="application/ld+json">` 로 그냥 박혀 있다(`docs/imweb_header_code.html` 664행).
같은 파일 **310행 부근에 이미 주소별로 넣는 틀이 있다** — `injectJSONLD()` 와 `var path = (location.pathname || "/")`.
FAQ 를 그 틀 안으로 옮기면 홈에서만 들어간다.

```js
// 헤더 코드 안의 기존 (function(){ ... var path = ... }) 블록 안쪽에 넣는다
if (path === "/" || path === "/index") {
  injectJSONLD({ "@context":"https://schema.org", "@type":"FAQPage", "mainEntity":[ /* 기존 질문 8개 그대로 */ ] });
}
```

그리고 바깥에 있던 `<script type="application/ld+json">` FAQ 블록은 지운다.

**왜** 화면에 없는 내용을 구조화 데이터로 선언하는 것은 구글 구조화 데이터 지침에 어긋난다.
전체 사이트의 구조화 데이터 신뢰를 깎을 수 있고, AI 답변이 세척 페이지를 인용하면서 설치 FAQ 를 섞어 말할 수 있다.

> 같은 헤더 코드의 VideoObject 조건이 `path==="/"||path==="/home"||path==="/introduce"` 다.
> `/home`·`/introduce` 는 비우기로 결정된 페이지이니, 이 조건에서도 두 주소를 같이 뺀다.

### ③ 홈 모바일 화면에는 H1 이 없다

아임웹은 PC·모바일 섹션이 두 벌이다. 홈의 H1 은 **PC 섹션에만 있다.**

실측 (`section_wrap` 의 `pc_section`/`mobile_section` 으로 소속을 판정):

```
홈   pc_section 50곳 / mobile_section 48곳
홈 H1 1개 → 소속: pc
```

구글은 모바일 화면을 기준으로 색인한다(모바일 우선 색인). PC 쪽 H1 만 있으면 색인 기준 화면에 대제목이 없는 셈이다.

**아임웹 어디에서** 디자인 모드에서 **모바일 화면**을 열고, 첫 화면의 큰 제목 위젯을 선택해 제목 태그를 H1 로 지정한다.
문구는 PC 와 같은 `상업공간을 위한 / 냉난방 솔루션의 기준을 / 만듭니다.` 를 그대로 둔다(이 슬로건은 고치지 않기로 결정된 문구다).

### ⑤ `/cleaning` 의 PC 제목에 '냉난방기 냉난방' 이 겹쳐 있다

### ⑥ 홈에 '전문건설업 **면허** 보유' 가 2곳 남아 있다

우리 표현 규칙은 기계설비공사 **등록** 업체이고 '면허'라고 쓰지 않는다(`.claude/product-marketing.md`).

실측 (홈 HTML, `/index` 도 같은 내용이라 같이 들어 있다):

```html
<div class="itg-trust-icon">

<h3> 전문건설업 면허 보유 </h3>
<p> 기계설비·가스공사업 …
```

같은 자리의 `/cleaning` 은 이미 '전문건설업 자격 보유'로 돼 있다.

**아임웹 어디에서** 디자인 모드 → 홈 → '현장에서 쌓아온 경험이 실력을 증명합니다' 아래 네 칸 중 두 번째.
글자(h3)와 **그 위 이미지의 대체 텍스트(alt)** 를 둘 다 고친다. PC·모바일 두 화면 모두.

고친 문구:


- 바꾼 이유: 우리는 기계설비공사 '등록' 업체다. '면허'는 사실과 다른 말이고, 등록 업종을 면허라고 적으면 표시광고 문제가 될 수 있다. '보유'는 '등록'과 겹쳐 뺐다.
- 확인 필요: 아래 설명 줄이 '기계설비·가스공사업'으로 시작하는데, 두 업종의 등록이 지금도 유효한지는 부장님이 확인해 주시면 좋겠다.

### ⑦ `/review1` — 차단은 이미 걸려 있다 (앞말 정정, 급하지 않음)

**이 항목의 처음 판은 틀렸다.** "검색엔진 노출을 껐다는 기록과 달리 차단이 안 걸려 있다"고 적었는데,
그것은 내 측정 실수였다. 다시 재니 **차단이 제대로 걸려 있다.**

실측 (홑따옴표까지 포함해 다시 셈):

```
$ curl -s https://www.itg-aircon.com/review1 | grep -oiE "<meta[^>]*name=['\"]robots['\"][^>]*>"
<meta name='robots' content='noindex, nofollow' />
```

| 항목 | 값 |
|---|---|
| 응답 | 200 |
| `robots` 메타 | **`noindex, nofollow`** — 걸려 있다 |
| canonical | `https://www.itg-aircon.com/review1` |
| title | `냉·난방기 \| 시스템 에어컨 전문 \| (주)아이티글로벌 고객 리뷰` ← 옛 사이트 제목 |
| 사이트맵 | 없음 |
| 내부 링크 | **0곳** (홈·세척·시공사례·후기·한전 6페이지 HTML 전수 조사) |
| 본문 | `커뮤니티 냉/난방 공조 시공 전문 법인 기업 \| 아이티글로벌 커뮤니티 전체` ← 옛 커뮤니티 게시판 |

**남은 일은 내용 비우기 하나다.** 차단·링크 끊김은 다 돼 있어 검색에는 나오지 않는다.
옛 페이지 4곳(`/introduce`·`/home`·`/35`·`/50`)과 묶어 같이 비우면 된다 — **급한 항목이 아니다.**

**왜 그래도 비우나** noindex 는 검색 색인만 막는다. AI 가 주소를 직접 가져가 읽는 것은 막지 못한다.
옛 사이트 제목과 '커뮤니티' 라는 내부 용어가 그 경로로 읽힐 수 있다. 이것이 옛 페이지 4곳을 '비우기'로 정한 이유와 같다.

### ⑧ 홈 후기 카드 — 사람은 `/review` 로 가지만, 구글은 아직 `/35` 를 본다 (정정)

**이 항목의 처음 판도 반만 맞았다.** 11-15 에 이미 손을 써 뒀다 — 다만 위젯 설정을 바꾼 것이 아니라
**헤더 코드에 넣은 자바스크립트로 링크를 갈아 끼우는 방식**이다.

실측 — 홈 헤더 코드 안의 주석과 코드:

```html
<!-- 후기 카드 링크 교정 (2026-11-15) ======================
     홈 '최신글' 위젯이 글 링크를 옛 페이지(/35)로 보내는데, 그 페이지에서는 게시판이 화면에
     그려지지 않아 글을 눌러도 빈 화면이 떴다. 같은 글이므로 고객 후기 페이지(/review)로 보낸다.
     위젯 설정에서 연결 게시판을 '고객 후기'로 바꾸면 이 코드는 지워도 된다. -->
<script>
  var list = document.querySelectorAll('a[href*="/35/?idx="],a[href*="/35?idx="]');
  … h.replace(/\/35\/?\?/, '/review/?') …
</script>
```

그래서 **사람이 누르면 `/review` 로 간다 — 빈 화면 문제는 해결돼 있다.**

그런데 HTML 소스의 `href` 는 그대로 `/35` 다:

```html
<a class="holder blocked _fade_link" href="/35/?idx=13773347&bmode=view">   ← 카드 1
<a class="holder blocked _fade_link" href="/35/?idx=13773268&bmode=view">   ← 카드 2
<a class="holder blocked _fade_link" href="/35/?idx=13773224&bmode=view">   ← 카드 3
```

구글은 HTML 의 `href` 를 보고 크롤링한다. 그리고 `/35` 는 `noindex, nofollow` 다(실측).
**결과: 후기 글은 여전히 검색에 하나도 색인되지 않는다.** `docs/imweb_page_meta.md` ② 에 적힌 문제가 그대로다.

**아임웹 어디에서** 디자인 모드 → 홈 → 후기 '최신글' 위젯 → **위젯 설정의 '연결 게시판'을 '고객 후기'로 바꾼다.**
그러면 `href` 자체가 `/review` 로 나오고, 11-15 에 넣은 교정 스크립트는 지워도 된다(주석에도 그렇게 적혀 있다).
PC·모바일 두 화면 모두 확인한다.

**왜** 지금 방식은 사람 눈에만 고쳐진 것이다. 검색·AI 쪽에는 후기 3건이 '색인 금지 페이지로 가는 링크'로 보인다.

참고 — 홈 HTML 의 내부 링크 전수:

```
/35                 <- ['/', '/index']
/cleaning           <- 6페이지 전부
/construction-case  <- 6페이지 전부
/event              <- 6페이지 전부
/index              <- 6페이지 전부        ← 메뉴 '홈' 이 /index 로 간다 (①)
/review             <- 6페이지 전부
/inquire_form       <- ['/', '/event', '/index']
/admin/sales_tool   <- ['/', '/construction-case', '/event', '/index', '/review']
```

위젯 설정을 바꾸는 일은 `/35` 를 비우기 **전에** 하는 쪽이 안전하다.

### ⑩ 아임웹이 자동으로 넣는 Organization 이 우리 것과 따로 선다

모든 페이지에 Organization 이 **두 개** 있다. 하나는 우리가 헤더 코드로 넣은 것, 하나는 아임웹 자동 생성이다.

우리 것(헤더 코드):
```json
{"@type":["Organization","HVACBusiness"],
 "@id":"https://www.itg-aircon.com/#organization",
 "name":"(주)아이티글로벌",
 "telephone":"+82-1899-1377",
 "address":{"streetAddress":"걸포로 134-84","addressLocality":"김포시","addressRegion":"경기도","postalCode":"10076"},
 "geo":{"latitude":37.6410894,"longitude":126.705937},
 "areaServed":[서울특별시, 경기도, 인천광역시],
 "sameAs":[인스타, 네이버블로그, 페이스북]}
```

아임웹 자동 생성:
```json
{"@type":"Organization",
 "name":"상업용 냉난방기 · 시스템에어컨 전문 | (주)아이티글로벌",   ← 회사 이름이 아니라 사이트 제목
 "address":{"streetAddress":"경기 김포시 걸포로 134-84 (걸포동)","postalCode":"10076"},  ← 한 칸에 뭉침
 "sameAs":["instagram.com/systemaircon_itg", ...]}                ← https:// 가 없다
```

`@id` 가 없어서 우리 것과 하나로 합쳐지지 않는다. 결과적으로 **회사 이름이 둘, 주소 형식이 둘**이다.

**바로 할 수 있는 한 가지** — `sameAs` 의 `instagram.com/systemaircon_itg` 에 `https://` 가 없는 것은
`docs/imweb_apply_checklist.md` 5번에 이미 적혀 있던 항목이고, **실측 결과 아직 적용되지 않았다.**
설정 → SNS 주소 칸의 인스타그램을 `https://www.instagram.com/systemaircon_itg/` 로 고치면 된다(1분).
스킴이 없으면 구조화 데이터에서 무효 값이 되어, 인스타 계정이 우리 회사와 같은 곳이라는 연결이 끊긴다.

**나머지는** 아임웹 자동 구조화 데이터를 끄는 칸이 있는지 **확인하지 못했다.** 3번 항목으로 넘긴다.
끌 수 없다면 우리 쪽 `@graph` 를 그대로 두는 것이 차선이다 — `@id` 와 `HVACBusiness` 가 있어 구글이 우리 것을 주 엔티티로 볼 가능성이 높다.

**왜** 지역 업체 검색과 AI 답변은 회사 이름·주소·전화를 이 데이터에서 가져간다. 이름이 '상업용 냉난방기 · 시스템에어컨 전문 | (주)아이티글로벌'로 읽히면 상호가 아니라 광고 문구로 보인다.

### ① 사이트맵이 차단 URL 6개를 제출하던 문제 — 해결됐다

지난 기록: "`sitemap.xml` 이 `/37`·`/48`·`/49`·`/50`·`/53`·`/54` 를 제출한다."
실측 결과 **지금 사이트맵에는 그 6개가 하나도 없다.** 5개만 있고 전부 정상이다.

```
/construction-case  200  canonical=자기자신  noindex 없음
/cleaning           200  canonical=자기자신  noindex 없음
/event              200  canonical=자기자신  noindex 없음
/review             200  canonical=자기자신  noindex 없음
/index              200  canonical=자기자신  noindex 없음   ← 1-① 참고
```

이것은 `docs/imweb_apply_checklist.md` 머리글의 "사이트맵 13개→6개" 기록과 맞는다(지금 5개인 것은 그 뒤 `/review1` 까지 빠진 것으로 보인다).

사이트맵에 올라간 주소 중 301·404·noindex 는 **하나도 없다.**

### ② 사이트맵 주소가 non-www 로 301 을 경유하던 문제 — 해결됐다

사이트맵의 다섯 주소가 전부 `https://www.itg-aircon.com/…` 다. 리다이렉트를 타지 않는다.
호스트 통합도 맞게 걸려 있다:

```
http://www.itg-aircon.com/  → 301 → https://www.itg-aircon.com/
https://itg-aircon.com/     → 301 → https://www.itg-aircon.com/
```

단 `https://itg-aircon.com/sitemap.xml` 은 301 없이 200 을 그대로 준다. 파일 안의 주소가 www 라서 실질 영향은 없다.

### ③ `/contact-board` canonical 이 로그인 URL 을 가리키는 문제 — 색인될 경로가 없다

실측:

```
/contact-board  → 302 → https://itg-aircon.com/login?back_url=L2NvbnRhY3QtYm9hcmQ%3D
                       → 200, canonical = .../login?back_url=...
```

canonical 이 로그인 URL 인 것은 지난 기록대로다. 다만 `/login` 은 robots.txt 에 `Disallow: /login` 이 걸려 있어 구글이 읽지 못하고,
`/contact-board` 는 사이트맵에도 내부 링크에도 없다. **지금 손댈 필요 없다.**

### ⑤ 제목·설명은 11-15 에 정한 값이 전부 반영돼 있다

다섯 페이지의 `<title>`·`description`·`og:description` 이 `docs/imweb_page_meta.md` 의 값과 일치한다.
옛 사이트 제목('냉·난방기 | 시스템 에어컨 전문 …')으로 시작하는 페이지는 살아 있는 5곳 중 **하나도 없다**.
(`/review1`·`/introduce`·`/54`·`/inquire_form` 에만 남아 있고, 앞 셋은 비우기·차단 대상이다.)

### ⑥ 빈 alt 7개 — 5개는 장식용이라 비어 있는 게 맞다

실측 — 홈의 `alt=""` 7곳:

```
mobile | <img src=".../b69df1ffee602.png" alt="">                       ← 내용 이미지로 보임
mobile | <img src=".../adcf2e092b0ab.jpg" style="visibility:hidden…">   ← 내용 이미지로 보임
mobile | <img src="/common/img/default_profile.png" alt="">   ×3        ← 후기 기본 프로필(장식)
mobile | <img class="itg-kakao-icon" … alt="" aria-hidden="true"> ×2     ← 아이콘(장식)
```

프로필 기본 이미지와 카카오 아이콘은 **장식용이라 `alt=""` 가 올바른 표기**다(둘은 `aria-hidden="true"` 까지 붙어 있다).
실제로 채울 가치가 있는 것은 위 2장이다. `alt` 속성이 아예 없는 `<img>` 는 페이스북 픽셀 1×1 추적 이미지 하나뿐이고, 이건 그대로 둬도 된다.

나머지 alt 는 잘 들어가 있다 — `천장형 시스템에어컨`, `상업용 스탠드 냉난방기`, `매립덕트형 냉난방기`, `전열교환기`, `OBS 생방송 어서옵쇼 냉난방기 전문가 출연` 등.
다만 로고 alt 4곳이 사이트 제목 전체(`상업용 냉난방기 · 시스템에어컨 전문 | (주)아이티글로벌`)로 들어가 있다. 아임웹 자동값이라 1-⑩ 과 같은 뿌리다.

### ⑦ `/review` 와 `/review1` 은 중복이 아니다

지난 기록에 "중복"으로 적혀 있었으나, 본문을 뽑아 비교하니 다른 게시판이다.

```
/review   … 아이티글로벌에게 공사를 맡겨주신 실제 고객 후기를 확인…
/review1  … 커뮤니티   냉/난방 공조 시공 전문 법인 기업 | 아이티글로벌   커뮤니티 전체 …
```

`/review` 가 지금 쓰는 후기 게시판이고, `/review1` 은 쓰지 않는 옛 커뮤니티다(1-⑦ 로 처리).
`docs/imweb_page_meta.md` 「확인 필요」의 **"/review 와 /review1 중 어느 쪽을 남길지"는 더 묻지 않아도 된다 — `/review` 다.**

### ⑧ H1 이 페이지마다 2개가 되는 문제 — 홈·시공사례는 1개다

PC·모바일 두 벌 때문에 H1 이 2개가 되기 쉽다고 봤는데, 실제로 그런 페이지는 `/cleaning` 하나뿐이다.
나머지는 오히려 **반대 문제**(H1 이 0개이거나 PC 쪽에만 있음)였다. 1-③·④ 로 처리.

### ⑨ 홈 JSON-LD 와 `pm.itg-aircon.com/company` 의 사실이 어긋나지 않는다

두 곳을 항목별로 맞춰 봤다.

| 항목 | 홈 (헤더 코드) | pm/company (`dashboard/blueprints/public_info.py`) | |
|---|---|---|---|
| `@id` | `https://www.itg-aircon.com/#organization` | 같음 | 일치 |
| `@type` | `["Organization","HVACBusiness"]` | 같음 | 일치 |
| name | (주)아이티글로벌 | 같음 | 일치 |
| telephone | +82-1899-1377 | 같음 | 일치 |
| 주소 | 걸포로 134-84 / 김포시 / 경기도 / 10076 | 같음 | 일치 |
| geo | 37.6410894, 126.705937 | 같음 | 일치 |
| areaServed | 서울특별시·경기도·인천광역시 (`AdministrativeArea` 객체) | 같은 세 곳 (문자열) | 사실 일치, 형식만 다름 |
| sameAs | 인스타·네이버블로그·페이스북 | 홈페이지·네이버블로그 | **다름** |

**사실이 어긋난 곳은 없다.** `sameAs` 목록만 다르다(3-⑤ 참고).

### ⑩ robots.txt 는 의도대로 동작하고 있다

실측 결과, 색인에서 빼야 할 주소에 `Disallow` 가 걸려 있지 않다 — 의도한 대로다.
아임웹 기본 블록이 우리 블록 앞에 붙어 두 그룹으로 보이지만, 구글은 같은 `User-agent: *` 그룹을 합쳐 읽는다.

```
User-agent: *                       ← 아임웹 자동
Allow: /
Disallow: /site_join …
User-agent: *                       ← 우리가 넣은 것
Disallow: /admin/ /login /cart /checkout /search /?mode*
Sitemap: https://www.itg-aircon.com/sitemap.xml
Sitemap: https://www.itg-aircon.com/sitemap.xml     ← 두 줄
```

`Sitemap` 이 두 줄 들어가 있다(아임웹 자동 + 우리 것). 같은 주소라 해롭지 않다.
`/llms.txt` 도 200 으로 살아 있다.

### ⑪ noindex 는 열 곳에 제대로 걸려 있다 — `imweb_page_meta.md` 의 11-17 기록이 틀렸다

이번 점검에서 가장 중요한 정정이다. `docs/imweb_page_meta.md` 「옛 페이지 4곳 — 색인 차단이 아니다 (2026-11-17 실측, 앞말 정정)」 절에 이렇게 적혀 있다.

> 네 페이지 모두 `robots` 메타가 없고(색인 허용), robots.txt 의 Disallow 목록에도 없다.

**이것은 사실이 아니다.** 네 곳 다 `noindex, nofollow` 가 걸려 있다.
그 절은 11-16 기록("검색 차단 상태라 급하지 않다")을 "사실이 아니다"라며 뒤집었는데, **원래 11-16 기록이 맞았다.**

실측 — 전체 18곳을 홑따옴표까지 포함해 다시 셌다:

```
$ curl -s https://www.itg-aircon.com$u | grep -oiE "<meta[^>]*name=['\"]robots['\"][^>]*>"
```

| 주소 | `robots` 메타 |
|---|---|
| `/` · `/index` · `/cleaning` · `/construction-case` · `/review` · `/event` | 없음 (색인 허용 — 의도대로) |
| `/review1` · `/introduce` · `/home` · `/35` · `/50` | **`noindex, nofollow`** |
| `/37` · `/48` · `/49` · `/53` · `/54` | **`noindex, nofollow`** |
| `/inquire_form` · `/itglobal-kps` | **`noindex, nofollow`** |

**왜 두 번이나 틀렸나** — 아임웹은 메타 태그를 **홑따옴표**로 쓴다(`<meta name='robots' …>`).
쌍따옴표로만 찾으면 한 건도 안 걸리고, 결과가 "전부 없음"으로 깔끔하게 나와 의심하기 어렵다.
나도 이 보고서 처음 판에서 같은 실수를 했다.

**앞으로 이 사이트의 메타를 셀 때는 반드시 `['\"]` 로 양쪽 따옴표를 다 찾는다.**

**결정에 미치는 영향** — 옛 페이지 4곳을 '비우기'로 정한 결론은 **그대로 유지된다.**
"차단이 하나도 안 걸린 채 방치돼 있다"는 근거 하나는 무너지지만, 더 중요한 근거가 남는다 —
**noindex 는 검색 색인만 막고, AI 가 주소를 직접 가져가 읽는 것은 막지 못한다.**
다만 **급한 일은 아니다.** 검색 결과에는 이미 나오지 않는다. 1번 항목들을 먼저 하고 그다음에 하면 된다.

## 3. 판단 보류 — 부장님 결정이 필요하다

### ① `/index` 를 어떻게 정리할지 (1-① 관련)

메뉴 '홈' 링크가 `/index` 로 돼 있어서, 이걸 `/` 로 바꾸는 작업이 아임웹 메뉴 구조를 건드린다.
아임웹 버전에 따라 첫 페이지를 `/` 로 지정하는 방식이 다를 수 있어, 화면을 못 본 상태에서 단계를 확정할 수 없다.
**메뉴 설정에서 '홈' 메뉴의 링크 칸이 어떻게 돼 있는지 한 번 봐 주시면** 그다음을 정할 수 있다.

### ② 아임웹 자동 구조화 데이터를 끌 수 있는지 (1-⑩ 관련)

사이트 설정의 SEO 쪽에 '구조화 데이터'·'스키마' 를 끄는 칸이 있는지 확인하지 못했다.
없으면 지금처럼 둘이 공존하는 수밖에 없다. 그 경우에도 우리 쪽 `@graph` 가 더 정확하니 손대지 않는다.

### ③ 이미지 지연 로딩 (1-⑨ 관련)

아임웹에 켜는 칸이 있는지 모른다. 없으면 기능 한계다.
`<img>` 24장이 대상이고 나머지는 CSS 배경이라, 켜도 체감 개선 폭은 크지 않을 수 있다.
TTFB 가 0.4초대로 느리지 않아 **급한 항목은 아니다.**

### ④ 지역·서비스 페이지를 새로 만들지

우리는 스킬이 말하는 '서비스 지역 업체'인데, 지금 사이트맵에 올라간 페이지는 5개뿐이고 **지역 페이지·장비별 페이지가 하나도 없다.**
고객이 쓰는 검색어('천장형 에어컨', '시스템에어컨 설치', 모델명)와 지역을 담을 자리가 없다는 뜻이다.

다만 스킬 기준(`references/local-seo.md`)은 **도시 이름만 바꿔 복제한 페이지를 만들지 말라**고 못 박는다.
지역 페이지는 그 지역만의 정보(실제 시공 현장, 그 지역 대응 방식)가 있을 때만 값이 있다.

우리에게는 재료가 있다 — 시공사례 게시글이다. 그래서 후보 두 갈래다.

1. **장비·서비스별 페이지**: 천장형 / 스탠드형 / 매립 덕트 / 전열교환기·FCU. 각각 설명·사례·견적 흐름이 다르다. 중복 걱정이 없고 검색어와 바로 맞는다.
2. **지역 페이지**: 서울·경기·인천 정도. 지역별 시공사례를 모아 붙일 수 있으면 값이 생기고, 그게 없으면 중복 페이지가 된다.

**어느 쪽부터 할지, 또는 하지 않을지는 부장님 결정이 필요하다.** 페이지를 만드는 일이라 품이 들고, 지금 점검 범위를 넘는다.

### ⑤ `pm.itg-aircon.com/company` 의 `sameAs` 에 인스타·페이스북을 넣을지

홈에는 인스타·네이버블로그·페이스북이 있고, pm 쪽에는 홈페이지·네이버블로그만 있다.
AI 가 둘 중 하나만 읽을 수 있으니 목록을 같게 두는 쪽이 낫다.
다만 **이건 코드 수정이고 서버 재시작이 필요하다** — 지금 이 작업 범위(아임웹 화면 고칠 목록) 밖이라 올려만 둔다.

### ⑥ 전화번호 형식 `+82-1899-1377`

구조화 데이터의 전화번호가 국제 형식으로 적혀 있는데, `1899` 대표번호는 해외에서 걸리지 않는다.
구글이 이 값을 그대로 쓰면 해외 화면에서 걸 수 없는 번호가 노출될 수 있다.
다만 국내 검색·지도에서 실제로 문제가 됐다는 근거를 확인하지 못했고, 구글 비즈니스 프로필에는 `1899-1377` 로 따로 들어가 있다.
**지금 바꾸자고 하기엔 근거가 부족하다.** 서치콘솔·프로필 쪽에서 번호가 이상하게 보이는 일이 생기면 그때 `1899-1377` 로 바꾼다.

### ⑦ `/admin/sales_tool` 링크가 공개 HTML 에 5곳 노출돼 있다

아임웹 게시판의 스팸 신고 안내 링크다(`fo_board_spam_guard_notice_link`).

```html
<a id="fo_board_spam_guard_notice_link" href="/admin/sales_tool?subPath=L3Bvc3Qtc3BhbS1ndWFyZA==" …>
```

`robots.txt` 에 `Disallow: /admin/` 이 있어 색인 위험은 없고, 눌러도 로그인이 필요하다.
관리자로 로그인한 상태에서만 보이는 링크인지는 확인하지 못했다. **지금 조치할 거리는 아니다.**

### ⑧ 서치콘솔 실제 색인 상태

이 점검은 공개 URL 만으로 했다. **어느 주소가 지금 색인에 들어 있는지는 확인하지 못했다.**
위 조치를 한 뒤 2~4주 후 서치콘솔 '페이지' 보고서에서 확인하면 좋을 것:

- `/` 가 색인됐는지, `/index` 가 '대체 표준 페이지' 로 빠졌는지
- `/review1`·`/introduce`·`/home`·`/35`·`/50` 이 색인에서 빠졌는지
- 사이트맵 제출 수와 색인 수 차이
