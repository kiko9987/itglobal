# 슬랙 전자결재 설계 (플렉스 워크플로우 대체)

작성 2026-10-30 · 상태: 양식 정의 확정, 구현 전

## 1. 목표

- 플렉스 워크플로우의 결재 양식을 슬랙으로 옮긴다.
- 결재 정보를 공사코드·시트·계산서와 연결해, 사람이 기억으로 하던 일을 줄인다.
  - 샛별님이 #영업_관리에 올리는 매입 계산서("어느 현장 건인지")를 자동으로 현장에 연결
  - 프로젝트별 원가(특히 기타비: 운반비·사다리차·크레인) 근거를 쌓음
  - 이카운트 매입 계산서 공사코드 지정(월 약 312건) 부담을 줄임

## 2. 전체 구조

```
입구 (일하는 자리)                        결재함
─────────────────────────────            ──────────────────────
샛별님 계산서 글 스레드 [📍 현장 지정]  ─┐
공사확정 카드 [📋 결재 요청 ▾]          ─┼─→  #전자결재 채널
#전자결재 고정 메뉴 / `/결재`           ─┘     (모든 결재 카드, 완료 전 고정,
                                               단계 기록, 참조자 전원 확인)
                                         └→ 시작한 자리에 "결재 올라감 → 링크"
```

- **전자결재 봇(새 슬랙 앱)** 이 모든 결재 카드와 버튼을 맡는다.
  - 버튼은 메시지를 올린 봇에게만 오므로, 결재 카드를 한 봇이 올려야 처리가 한 곳에서 끝난다.
  - `im:write` 를 처음부터 받아 결재 DM을 직접 보낸다.
  - 설치용 manifest 는 `docs/slack_docview_manifest.yml` 과 같은 방식으로 만든다.
- 예외: 공사확정 카드의 드롭다운은 공사봇 카드라 공사봇이 모달을 열고, 제출 내용을 결재 엔진에 넘겨 전자결재 봇으로 카드를 올린다(금액 수정 요청이 이미 쓰는 봇 간 연계 방식).
- 양식마다 따로 개발하지 않는다. **양식 = 입력 칸 + 결재선 + 완료 후 동작** 정의만 추가하면 같은 엔진이 처리한다.

## 3. 결재선 두 가지

| 유형 | 결재선 | 버튼 | 누를 수 있는 사람 |
|---|---|---|---|
| **지출형** | ① 승인 → ② 이체 완료 | ① [승인] [반려(사유)] ② [이체 완료] | ① 승인자(고광일) ② 이체 담당(경영지원 명단) |
| **업무요청형** | ① 처리 완료 | [접수] → [처리 완료] 또는 결과 파일을 스레드에 올리면 자동 완료 | 처리 담당(경영지원 명단) |

- 플렉스의 2단계(샛별 "승인")는 실제로는 **이체했다는 알림**이었다 → 슬랙에서는 [이체 완료] 로 이름을 바로잡는다.
- 단계마다: 원래 카드 갱신 + 스레드 기록 댓글(채널에도 함께 보내기) + 다음 처리자·기안자 DM.
- 승인자·이체 담당·처리 담당은 설정 명단으로 둔다(샛별님 부재 대비). 서버 재시작 없이 바꿀 수 있게 한다.
- 승인자가 직접 기안하면 ① 승인은 자동 통과(확인 필요 — 8장).

## 4. 양식 정의 (플렉스 15종 → 8종)

표기: **자동** = 공사현황·기존 데이터에서 채움 / **기억** = 같은 거래처·사람이 예전에 입력한 값으로 채움.

### 4-1. 자금집행 (지출형) — 플렉스 3종 통합

전자계산서용·수기계산서용·N/기타영수증용을 「증빙 종류」 선택 하나로 합친다.

| 칸 | 입력 |
|---|---|
| 증빙 종류 | 전자계산서 / 수기계산서 / 기타영수증 |
| 프로젝트 | 검색 선택 + 「프로젝트0」(회사 재고 자재 구매 — 비품보다 많음)·「공통비」(11-02). 비품 신청은 사무용 비품 구매용으로 따로 |
| 프로젝트 주소 | 자동 |
| 고객 견적금액(VAT별도) | 자동(총액 1) |
| 사업자구분 | 자동(G/R). 기타영수증은 N 선택 가능 |
| 원가 분류 | 제품대 / 도급비 / 자재비 / 기타비(운반비·사다리차·크레인·폐기물·기타) |
| 내용 | 입력 |
| 상호 | 검색 선택(거래처 탭) 또는 입력 |
| 예금주·은행·계좌 | 기억(상호 기준), 처음엔 입력 |
| 총 금액(VAT포함) | 입력 |
| 집행 시기 | 일반 / 긴급 |
| 비고 | 입력 |
| 첨부 | 견적서·계산서·영수증. 스레드에 올림 |

- 수기계산서를 고르면 원가 분류 기본값 = 기타비·운반비.
- 수기계산서 첨부는 공유 드라이브 `★아이티글로벌 거래처(자재,공구)AS\★운반비 수기세금계산서\{연도}년` 에도 자동 저장(플렉스 안내문 3번을 대신함).
- 첨부 견적서 합계와 입력 금액이 다르면 경고.

**입구 A — 샛별님 계산서 글 (부대비용, 가장 많음)**
1. 샛별님이 #영업_관리에 `10/29 G 533,500원 강원포장 회신 바랍니다.` + 계산서 이미지.
2. 자동 고정과 함께 스레드에 [📍 현장 지정] 버튼.
3. 모달: 날짜·G/R·금액·상호 미리 채움 → 프로젝트·원가 분류 선택, 「이체 필요」 체크.
4. 이체 불필요 → 스레드에 `✅ G4049-JW · 기타비(운반비) · 박정우 지정`, 고정 해제(회신 끝).
   이체 필요 → 위와 같이 지정 + 자금집행 결재 시작(#전자결재 카드).
- 매니저 누구나 누를 수 있다(글에 담당자가 없음).
- 계산서 이미지 OCR(공급자 사업자번호·품목)로 거래처 계좌 기억·원가 분류 추천 — 2차.

**입구 B — 공사확정 카드(선결제)·메뉴(현장 무관)**: 위 칸 그대로.

**11-01 입구 통일**: 어디서 열든 같은 자금집행 창. 맨 위 「계산서」에서 #영업_관리에 고정된(처리 전)·현장 미지정
계산서 글을 고르면 거래처·금액·G/R 은 그 글 값으로 숨기고, 제출하면 그 글의 현장 지정(답글·버튼 정리·고정 해제)까지
같이 끝난다(`finish_pinv_assignment`). 「계산서 없음」=선지급. 계산서 글의 [📍 현장 지정]은 지름길로 그대로 둔다.
매니저 규칙은 하나: "자금집행은 아무 데서나 누르면 된다". 같은 계산서 중복 요청은 막는다.

### 4-3. 비품 신청 (지출형)

| 칸 | 입력 |
|---|---|
| 품명 | 입력 |
| 상품 정보(링크) | 입력, 필수 |
| 수량 · 단가(VAT포함) | 입력 |
| 금액(VAT포함) | 자동(수량 × 단가), 수정 가능 |
| 휴대폰번호 | 자동(기안자) |
| 사유 | 입력 |
| 첨부 | 기존 캡처 사진 또는 링크 |

- 플렉스 이름 「비품 신청(프로젝트0)」 → 기본 프로젝트 = 프로젝트0.
- 사업자 구분 칸은 비품 신청·개인경비 청구에 두지 않는다(11-05) — 플렉스도 없었고(89건·61건), 어느 통장에서 나갈지는 경영지원이 판단. 자금집행·법인서류만 필수.
- **구현(11-01)**: #전자_결재 메뉴 [🛒 비품 신청]. 프로젝트0 고정. 결재선 = ① 승인 → ② **구매 완료**(경영지원, 이체 대신).
  휴대폰번호 칸은 뺐다(요청자가 카드에 나옴). 상품 링크·수량·단가·사유는 `approvals.extra`(JSON) 에.

### 4-4. 계약서 작성 요청 (업무요청형) — G/R 통합

| 칸 | 입력 |
|---|---|
| 프로젝트·주소·사업자구분 | 자동 |
| 견적서 경로 | 자동(공사현황 '견적서 및 계약서 폴더 경로') |
| 계약금·중도금·잔금(VAT포함)과 입금 일자 | 자동(시트), 수정 가능 |
| 총 금액(VAT포함) | 자동(총액 2) |
| 인수자명·연락처 | 자동(현장 담당자·연락처), 수정 가능 |
| 납기 및 제품 인도 기간 | 입력 |
| 계약서 발송 방법 | 이메일 / 카카오톡 / 대면 |
| 이메일 또는 전화번호 | 자동(담당자 이메일·연락처), 수정 가능 |

- 사업자등록증 필수 → 공사확정 카드 스레드에 이미 있으면 자동 확인, 없으면 경고.
- 안내: 계약·선급·하자 보증보험 발행 요청 시 계약서에 기재(보증금율·기간).
- 완료: 경영지원이 계약서 파일을 스레드에 올리면 자동 완료.

### 4-7. 현금영수증 발행 (업무요청형) — 세금계산서 요청에 합침

- 기존 공사확정 카드 [🧾 세금계산서 요청] 모달에 증빙 종류 「현금영수증」 추가.
- 칸: 발급 번호 하나 → `010…` = 소득공제용, 사업자번호 10자리 = 지출증빙용 자동 판정(사업자번호는 국세청 상태 조회). 금액·비고.
- 플렉스의 「거래용도」·「발급수단」 두 칸은 번호 한 칸으로 대체.

## 5. 저장

- `users.db` 에 결재 표(서비스가 스스로 만드는 방식, `ecount_sales.py` 와 같음).
  - `approvals`: 번호, 양식, 기안자, 프로젝트, 원가 분류, 금액, 칸 값(JSON), 상태, 채널·카드 ts, 시작 위치(스레드 ts)
  - `approval_steps`: 결재 번호, 단계, 처리자, 결과(승인/반려/이체 완료/처리 완료), 사유, 시각
  - `payee_accounts`: 상호(사업자번호)·사람 → 예금주·은행·계좌, 마지막 사용일
- Redis 기한 키가 아니라 DB에 영구 보관(돈 관련 기록).
- 감사로그(`audit_logs`)에도 단계별 기록.
- 첨부 파일: 해당 프로젝트 드라이브 폴더(`_project_folder_id_for`), 프로젝트0·공통비는 별도 폴더.

## 7. 기존 시스템 제약 (조사 결과)

- 봇마다 별도 슬랙 앱. 버튼은 그 메시지를 올린 봇에만 오고, 그 봇만 카드를 고칠 수 있다.
- 기존 봇 중 DM 권한(`im:write`)은 메인봇뿐.
- 승인 권한 명단(`settlement_checkers`)은 서버 시작 때 한 번 읽고, 경영지원 할 일 DM은 명단 첫 줄(샛별님)에게만 간다 → 결재용 역할 명단은 따로 둔다.
- 모달 파일 첨부(`file_input`)는 쓴 적 없음 → 스레드 첨부 방식 유지.
- 거래처 계좌는 어디에도 저장돼 있지 않음 → `payee_accounts` 신설.
- #영업_관리 ✅ 는 경영지원 권한자가 눌러 고정을 푸는 "처리 끝" 표시(봇이 다는 게 아님).
