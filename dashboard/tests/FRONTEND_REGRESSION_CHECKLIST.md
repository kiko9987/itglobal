## 📋 테스트 개요

이 체크리스트는 다음 변경사항 이후 프론트엔드 기능의 정상 동작을 검증합니다:
- DataManager 캐시 구조 변경
- Redis 전환 및 Fallback 모드 추가
- Optimistic Lock (_version) 추가
- 메모 저장 캐시 무효화 최적화
- 409 충돌 병합 UI 개선

## 1. 데이터 로딩 및 캐싱 (DataManager)

### 1.1 초기 로딩
- [ ] **첫 방문**: 프로젝트 리스트 페이지 접속 시 데이터 로드됨
- [ ] **로딩 시간**: 초기 로딩이 5초 이내 완료
- [ ] **데이터 표시**: 모든 프로젝트가 테이블에 정상 표시됨
- [ ] **콘솔 로그**: 개발자 도구에서 "[DataManager] 서버에서 새 데이터 로드" 확인

### 1.2 캐시 동작
- [ ] **캐시 히트**: 페이지 새로고침(F5) 시 "[DataManager] 캐시된 데이터 사용" 로그 확인
- [ ] **TTL 만료**: 30초 대기 후 새로고침 시 서버에서 재로드
- [ ] **강제 새로고침**: Ctrl+Shift+R 시 캐시 무시하고 서버에서 로드
- [ ] **localStorage**: 개발자 도구 → Application → Local Storage에서 `itg_dashboard_v1.0_project_data` 키 확인

### 1.3 캐시 버전 관리
- [ ] **버전 업그레이드**: localStorage에서 `itg_dashboard_v1.0_version`을 `0.9`로 변경 후 새로고침 → 자동으로 캐시 클리어되고 재로드

## 2. 프로젝트 필터링 및 정렬

### 2.1 필터 기능
- [ ] **담당자 필터**: 담당자 드롭다운에서 특정 담당자 선택 → 해당 담당자 프로젝트만 표시
- [ ] **진행 상태 필터**: 진행 상태(진행 중/완료/취소) 필터 적용 → 정확한 결과 반환
- [ ] **검색창**: 검색어 입력(예: 회사명) → 실시간 필터링 동작
- [ ] **다중 필터**: 담당자 + 진행 상태 동시 적용 → 교집합 결과 정확
- [ ] **필터 초기화**: "필터 초기화" 버튼 클릭 → 모든 필터 해제되고 전체 데이터 표시

### 2.2 정렬 기능
- [ ] **프로젝트 코드 정렬**: 프로젝트 코드 헤더 클릭 → 오름차순/내림차순 정렬
- [ ] **날짜 정렬**: 시공시작일 헤더 클릭 → 날짜 기준 정렬 (최신순/과거순)
- [ ] **담당자 정렬**: 담당자 헤더 클릭 → 가나다순 정렬
- [ ] **정렬 유지**: 정렬 후 필터 적용 시에도 정렬 순서 유지

### 2.3 필터/정렬 + 캐시 통합
- [ ] **캐시된 데이터 필터링**: 페이지 새로고침(캐시 히트) 후 필터 적용 → 정상 동작
- [ ] **캐시된 데이터 정렬**: 캐시에서 로드된 데이터도 정렬 가능
- [ ] **_version 필드**: 프로젝트 행 확장 시 _version 필드가 데이터에 포함되어 있음 (개발자 도구 확인)

## 3. 인라인 편집 및 Optimistic Lock

### 3.1 편집 모드 진입/해제
- [ ] **편집 모드 진입**: 프로젝트 행의 "수정" 버튼 클릭 → 필드들이 편집 가능 상태로 변경
- [ ] **편집 모드 해제**: "취소" 버튼 클릭 → 변경사항 취소되고 읽기 모드로 복귀
- [ ] **락 획득**: 편집 모드 진입 시 락 획득 성공 (다른 사용자가 편집 불가)

### 3.2 정상 편집 Flow
- [ ] **필드 수정**: 담당자 이름 변경 → 입력 정상 동작
- [ ] **저장 성공**: "저장" 버튼 클릭 → 200 OK, "저장 성공" 메시지 표시
- [ ] **버전 증가**: 저장 후 _version이 0 → 1로 증가 (개발자 도구 Network 탭 확인)
- [ ] **락 해제**: 저장 완료 후 락 자동 해제
- [ ] **캐시 무효화**: 저장 후 다음 페이지 로드 시 최신 데이터 반영

### 3.3 Optimistic Lock 충돌 (409)
- [ ] **충돌 시나리오**:
  1. 브라우저 A에서 프로젝트 편집 시작
  2. 브라우저 B에서 동일 프로젝트 먼저 저장
  3. 브라우저 A에서 저장 시도 → 409 Conflict 응답
- [ ] **충돌 알림**: 409 발생 시 "다른 사용자가 이 프로젝트를 먼저 수정했습니다" 알림창 표시
- [ ] **최신 데이터 반영**: 알림창에서 확인 시 브라우저 A에 최신 데이터 자동 업데이트
- [ ] **사용자 선택**:
  - 확인 클릭 → 편집 모드 유지, 최신 데이터 기준으로 계속 편집 가능
  - 취소 클릭 → 편집 모드 종료
- [ ] **콘솔 로그**: "[409 병합] 사용자가 계속 편집 선택" 또는 "[409 병합] 사용자가 편집 종료 선택" 확인

## 4. 메모 저장 기능

### 4.1 메모 저장
- [ ] **메모 작성**: 계약금 필드의 메모 아이콘 클릭 → 메모 입력창 표시
- [ ] **메모 저장**: 메모 입력 후 저장 → 200 OK, "메모 저장 완료" 메시지
- [ ] **메모 표시**: 저장된 메모가 아이콘에 표시됨 (색상 변경 등)
- [ ] **메모 조회**: 메모 아이콘 다시 클릭 → 저장된 메모 내용 표시

### 4.2 메모 캐시 동작 (MED-4 피드백 반영)
- [ ] **선택적 무효화**: 메모 저장 후 프로젝트 캐시는 유지, cell_notes 캐시만 무효화
- [ ] **메모 저장 후**: 페이지 새로고침 시 프로젝트 데이터는 캐시에서 로드 (빠름)
- [ ] **메모 반영**: 저장된 메모는 새로고침 후에도 정상 표시

---

## 5. 모드 변경 및 데이터 Flow

### 5.1 테이블 모드 변경
- [ ] **읽기 모드 → 편집 모드**: 프로젝트 수정 버튼 클릭 → 데이터 유지
- [ ] **편집 모드 → 읽기 모드**: 저장 또는 취소 → 데이터 유실 없음
- [ ] **로그 레벨**: 콘솔에 모드 변경 로그가 'debug' 레벨로 출력 (info 레벨 아님, MED-5 반영)

### 5.2 아코디언 확장/축소
- [ ] **프로젝트 확장**: 프로젝트 행 클릭 → 상세 정보 아코디언 확장
- [ ] **데이터 일관성**: 확장된 아코디언의 데이터가 테이블 행 데이터와 일치
- [ ] **축소 후 재확장**: 축소 후 다시 확장 → 데이터 유지됨

### 5.3 페이지 전환
- [ ] **다른 페이지 이동**: 프로젝트 리스트 → 통계 페이지 이동 → 데이터 유실 없음
- [ ] **뒤로 가기**: 브라우저 뒤로 가기 → 프로젝트 리스트 상태 복원 (캐시 활용)

## 6. 에러 처리 및 Fallback

### 6.1 서버 에러
- [ ] **500 에러**: 서버 다운 시 에러 메시지 표시, 사용자 친화적 안내
- [ ] **네트워크 타임아웃**: 느린 네트워크 시 로딩 인디케이터 표시

### 6.2 Redis Fallback (서버 관리자 전용)
- [ ] **Redis 다운**: Redis 중단 시 In-memory fallback 자동 전환
- [ ] **Fallback 모드 동작**: Fallback 모드에서도 프로젝트 리스트 정상 표시
- [ ] **Fallback 로그**: 콘솔에 "[FALLBACK] Redis 불가, In-memory 캐시 사용" 로그 확인

## 10. 회귀 테스트 (기존 기능 확인)

### 10.1 프로젝트 생성
- [ ] **자동 생성**: 프로젝트 자동 생성 → 프로젝트 코드 자동 생성, 리스트에 추가됨
- [ ] **버전 초기화**: 신규 프로젝트의 _version이 0으로 설정 (HIGH-1 반영)

### 10.2 금액 필드 (HIGH-2 반영)
- [ ] **통화 포맷**: 계약금 입력 시 "₩1,000,000" 형식 허용

- [ ] **검증**: 다른 통화 기호($, €, £) 입력 시 에러 메시지

### 10.3 프로젝트 재개 (POLISH-1 반영)
- [ ] **이미 정상 상태**: 정상 프로젝트 재개 시도 → 200 OK, "이미 정상 상태입니다" 메시지
