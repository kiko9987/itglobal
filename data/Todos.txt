 현재 상황 요약

  - static/legacy/css/project-list.css가 여전히 대용량 스타일을 들고 있고, 새 모듈(project-table.css, project-list-
  page.css, mobile-card-view.css 등)로 옮겨온 것은 그중 일부뿐입니다.
  - 레거시 파일 안에는 테이블 이외에도 필터, 모달, 토스트, 응급 버튼, 다양한 유틸 클래스까지 섞여 있는데, 이 부분을 현대
  모듈에 모두 분해하지 않았습니다.
  - 결국 manifest가 비면 해당 레거시 CSS가 필요하고, 폴백을 없애려면 스타일이 1:1로 현대화되어 있어야 합니다.

  완전한 현대화를 위한 작업 로드맵

  1. 레거시 CSS 전체 분석
      - static/legacy/css/project-list.css를 기능 단위로 나누고, 어떤 부분이 새 모듈에 이미 포함됐는지, 어떤 부분이 빠져
  있는지 목록화합니다.
      - modern_project_list.html과 JS 컴포넌트에서 쓰는 클래스 이름을 전부 추출해 레거시 파일과 교차 확인하는 작업이 필
  요합니다.
  2. 모듈 추가 및 보강
      - 누락된 영역(필터, 모달, 토스트, 알림, 버튼 유틸, 애니메이션 등)을 새 CSS 모듈로 정리합니다.
      - 공통적인 유틸/레이아웃은 design-system 또는 전역 유틸 파일로 분리해, 중복 이상 관리가 까다롭지 않도록 합니다.
  3. 검증 및 폴백 제거
      - 모든 레거시 스타일이 새 모듈에서 제공되는지 확인하기 위해 Percy·Storybook·Playwright 같은 시각/동작 테스트를 활
  용하면 좋습니다.
      - 검증이 끝나면 frontend_helpers.py 폴백을 제거하고 /static/legacy/css/*.css를 삭제, manifest 누락 시엔 배포 실패
  로 간주하도록 빌드 정책을 바꿉니다.

  결론
  지금은 “모던 페이지가 새 CSS를 기본으로 쓰는 상태”에 가까울 뿐, 레거시 CSS 전체가 완전히 모듈화되었다고 보기엔 이른 상
  태입니다. 말씀처럼 누락된 스타일이 많으므로, 위와 같은 전수 조사를 거쳐 레거시 파일을 쪼개고 새 구조로 옮긴 뒤 폴백을
  제거하는 단계까지 진행해야 진짜 현대화가 완료됩니다.
