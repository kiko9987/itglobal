  1. Session Management - 401 재로그인 무한 루프 위험

  위치: dashboard/src/js/utils/authInterceptor.js

  문제점:
  - 401 응답 시 /login으로 리다이렉트하지만, 이미 로그인 페이지에 있을 때도 계속 리다이렉트 시도
  - 백그라운드 polling(예: 자동 새로고침)이 401을 받으면 사용자가 편집 중이어도 강제 리다이렉트
  - 세션 만료 전 사용자에게 경고 없음

  영향도: 높음 - 사용자가 편집 중인 데이터를 잃을 수 있음

  현재 코드:
  if (error.response?.status === 401) {
      console.warn('[Auth] 인증 실패, 로그인 페이지로 이동');
      window.location.href = '/login';
  }

  위치: dashboard/blueprints/projects.py (lines 409-598)

  문제점:

  - Rate limit 에러 발생 시 재시도 로직 없음
  - 데이터 손실 가능성

  현재 에러 처리:
  except Exception as e:

      return jsonify({'error': str(e)}), 500

  영향도: 높음 - 프로덕션 환경에서 여러 사용자 사용 시 필수

  3. Field Lock 만료 후 충돌 가능성

  위치: dashboard/utils/field_lock_manager.py (line 25)

  문제점:
  - Lock timeout 5분 (300초) 후 자동 해제
  - 사용자 A가 5분 이상 편집 → Lock 만료 → 사용자 B가 같은 필드 편집 → 둘 다 저장 시도 → 데이터 충돌

  현재 코드:
  self.lock_timeout = 300  # 5분 타임아웃

  영향도: 중간 - 긴 시간 편집하는 사용자가 있을 경우

          // ... 복원 로직
      });
  }
