  주지 않는 project.id를 기대합니다. 모달로 신규·수정 시도 시 항상 실패하며, 저장 성공 이벤트(projectUpdated)만 남습니다. → 기존 /api/projects POST, /api/
  projects/<code> PUT 흐름에 맞춰 API 호출/페이로드를 재구성하거나, 서버에 새 엔드포인트를 추가해야 합니다.
  - dashboard/src/js/components/InlineEditor.js:296는 /api/projects/update-field로 PATCH를 보내지만 백엔드는 해당 라우트를 제공하지 않습니다. 또한
  FieldLockManager가 잠금 요청을 시도할 뿐 실제 socketio.emit('card_locked')/'card_unlocked'에 연결되지 않아 인라인 편집이 정상 동작하지 않습니다.

  ### 컨버팅 재가이드

  1. 기능 분해/로드맵
      - 레거시 static/js/project-list.js에서 기능 단위를 분리(필터, 테이블, 행 아코디언, 인라인 편집, 액션 버튼, 요약 카드, 소켓, 캐시관리 등)해 체크리스트를
  만들고, Vite 모듈과 1:1 대응시키세요.
  2. 핵심 컴포넌트 연결
      - ProjectListApp.loadComponents()에서 ProjectRowAccordion, ActionButtons, SocketManager, StatusBadge 등을 실제로 초기화하고, DataTable 초기화 후
  accordion.attachToTable(...)을 호출해 행 확장을 활성화합니다.
      - 인라인 편집이 제대로 동작하도록 기존 /api/update-project-inline을 재사용하거나, 새 엔드포인트(/api/projects/update-field)를 서버에 구현하고 권한/락
  로직과 매칭하세요.
  3. UI/DOM 보강
      - 요약 카드, 상태 뱃지, 컬러 스킴 등 기존 템플릿의 구조를 modern_project_list.html에 이식하거나 컴포넌트화합니다. 지금 DOM이 없는 상태에서 JS만 남겨두
  면 “기능이 돌아가지 않는” 코드가 됩니다.
      - 필터 패널에서 실제 사용하는 셀렉터 값(company/managers/outstanding)을 API로 로드해 ProjectFilters에 연결하고, 선택 시 applyFilters()가 해당 값으로 필
  터링하도록 원본 로직을 옮기세요.
  4. 소켓/락/브로드캐스트
      - SocketManager를 활성화해 card_locked/card_unlocked/new_project_added 등 이벤트를 듣고, InlineEditor/ProjectRowAccordion과 연계합니다.
      - LocalStorage 브로드캐스트(newProjectCreated, lockUpdateTrigger 등)를 그대로 포팅해 브라우저 간 상태 동기화를 복원하세요.
  5. API 레이어 정리
      - /api/projects/update, /api/projects/create, /api/projects/update-field 등 새로 만든 REST 네이밍을 실제 백엔드에 구현하거나, 기존 컨트롤러(/api/
  projects, /api/projects/<코드> 등)로 다시 통일하세요. 프론트가 잘못된 엔드포인트를 쓰면 기능 검증이 불가능합니다.
  6. 불필요한 모듈 정리
      - 실제로 쓸 계획이 없는 PerformanceOptimizer, AdvancedFilters 등은 제거해 번들 크기를 줄이고, 꼭 필요한 기능만 남겨 재사용성 있는 구조로 다듬으세요.

  요컨대, “기능별 모듈은 작성됐지만 연결이 빠져 있어 동작하지 않는다”가 현재 상태입니다. 원본 화면과 동일한 경험을 제공하려면 각 모듈을 실제 UI/이벤트/서버
  API와 엮고, 불필요한 코드와 잘못된 엔드포인트를 정리하는 작업이 필요합니다.
