  핵심 문제

  "동시 수정"이 아니라 "데이터 소스 혼란"입니다:

  1. DOM: 사용자가 직접 타이핑한 최신 값
  2. this.currentProject: 메모 UI 등에서 업데이트된 값
  3. DataTable: 편집 시작 전 서버 값 (가장 오래됨)

  collectAllChanges()가 이 3개를 혼합해서 읽는데, 우선순위 로직이 불명확합니다:

  // Line 4509: 먼저 currentProject 읽음
  let currentMemo = this.currentProject?.[memoField] || '';

  // Line 4512-4518: 그런데 DataTable이 있으면 덮어씀!
  if (row && row[memoField] !== undefined) {
    currentMemo = row[memoField] || '';  // this.currentProject 무시!
  }

  왜 DataTable을 우선하는가?
  - 주석에는 "최신 값"이라고 되어 있지만
  - 실제로는 DataTable이 편집 중인 값보다 오래된 값입니다
  - 편집 중에는 this.currentProject가 최신입니다

  정리

  사용자 지적이 맞습니다:
  - ✅ 프로젝트 잠금 → 다른 사용자 동시 수정 불가
  - ✅ Socket.IO 비활성화 → 자동 새로고침 없음

  그럼 문제가 없나요? 아닙니다:
  - ❌ 같은 탭 내에서 DOM, currentProject, DataTable이 서로 다른 값
  - ❌ collectAllChanges()가 어느 소스를 신뢰해야 할지 불명확
  - ❌ DataTable 우선 로직이 편집 중인 값을 덮어쓸 위험

  해결책은 동일합니다:
  - EditState 같은 단일 진실 소스
  - 모든 변경을 한 곳으로 라우팅
  - 저장 시 한 곳만 참조

  이건 "동시성" 문제가 아니라 "데이터 아키텍처" 문제입니다.

  실제로 버그가 발생할 확률은 낮지만, 발생하면 디버깅이 매우 어렵고, 코드 복잡도가 불필요하게 높습니다.

  데이터 흐름 비교

  Before (기존)

  사용자 입력 → DOM input.value
                  ↓
           collectAllChanges()
                  ↓
          5개 소스 순회하며 수집
                  ↓
          우선순위 혼란 발생
                  ↓
             서버 전송

  After (신규)

  사용자 입력 → input event → editState.updateField()
                                        ↓
  메모 변경 → updateLocalMemoData() → editState.updateField()
                                        ↓
                                editState.currentData
                                        ↓
                            collectAllChanges()
                                        ↓
                           editState.collectChanges()
                                        ↓
                                서버 전송

  장점

  1. 명확한 데이터 흐름: 모든 변경 → EditState → 서버
  2. 버그 추적 용이: EditState.debug() 한 번이면 전체 상태 파악
  3. 코드 단순화: collectAllChanges() 200줄 → 1줄
  4. 테스트 가능: EditState 단위 테스트 작성 가능
  5. Race Condition 제거: 단일 소스이므로 동기화 이슈 없음
