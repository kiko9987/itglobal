```javascript
// ✅ crypto.randomUUID() 적용 완료 (폴백 포함)

generateSessionId() {
  // 브라우저가 crypto.randomUUID()를 지원하면 사용
  if (typeof crypto !== 'undefined' && typeof crypto.randomUUID === 'function') {
    return crypto.randomUUID();
  }

  // 폴백: crypto.getRandomValues() 사용 (UUID v4 형식)
  if (typeof crypto !== 'undefined' && typeof crypto.getRandomValues === 'function') {
    const array = new Uint8Array(16);
    crypto.getRandomValues(array);
    array[6] = (array[6] & 0x0f) | 0x40; // version 4
    array[8] = (array[8] & 0x3f) | 0x80; // variant
    const hex = Array.from(array, byte => byte.toString(16).padStart(2, '0')).join('');
    return `${hex.slice(0, 8)}-${hex.slice(8, 12)}-${hex.slice(12, 16)}-${hex.slice(16, 20)}-${hex.slice(20)}`;
  }

  // 최종 폴백 (매우 오래된 브라우저)
  logger.warn('[SocketManager] crypto API를 사용할 수 없습니다. 약한 난수 생성기를 사용합니다.');
  return Date.now().toString(36) + Math.random().toString(36).substr(2);
}
```

### 1. **Lock 연장 로직의 Race Condition**
**위치**: `dashboard/utils/project_lock_manager.py:84-91`

**문제점**:
```python
if existing_lock.user_email == user_email and existing_lock.tab_id == tab_id:
    # 같은 사용자 + 같은 탭이면 잠금 연장
    existing_lock.expires_at = datetime.now() + timedelta(minutes=self.lock_timeout_minutes)
```

**시나리오**:
1. 사용자 A가 1분 55초에 lock 연장 요청을 보냄
2. 네트워크 지연으로 요청이 2분 5초에 서버 도착
3. 이미 lock이 만료되어 삭제됨
4. 사용자 B가 2분 3초에 lock 획득
5. 사용자 A의 연장 요청이 도착하면 새 lock 생성 시도 → B의 lock과 충돌

**권장 해결책**:
```python
# Grace period 추가
GRACE_PERIOD_SECONDS = 30

if existing_lock:
    # 만료되었지만 grace period 내라면 원래 사용자만 재획득 가능
    if datetime.now() > existing_lock.expires_at:
        grace_deadline = existing_lock.expires_at + timedelta(seconds=GRACE_PERIOD_SECONDS)
        if datetime.now() <= grace_deadline and existing_lock.user_email == user_email:
            # 원래 사용자가 grace period 내에 재획득
            existing_lock.expires_at = datetime.now() + timedelta(minutes=self.lock_timeout_minutes)
            return {'success': True, 'message': '잠금이 복구되었습니다.'}
```

### 2. ✅ **authInterceptor의 이중 리다이렉트 방지 로직 불완전** - 해결 완료 (f1652ea, 357835c)
**위치**: `dashboard/src/js/utils/authInterceptor.js:167-171`

**문제점**:
```javascript
if (isRedirecting) {
  return response;  // 이미 리다이렉트 중
}
isRedirecting = true;
```

**시나리오**:
- 사용자가 탭 A, B를 동시에 열어놓음
- 세션 만료로 탭 A에서 401 발생 → `isRedirecting = true` → 리다이렉트
- 탭 B에서도 거의 동시에 401 발생
- 하지만 `isRedirecting`은 탭 A의 메모리에만 존재 (탭 간 공유 안 됨)
- 탭 B도 별도로 리다이렉트 시도 → `sessionStorage.setItem('returnUrl', ...)` 덮어쓰기

**결과**: 두 탭 중 나중 것의 returnUrl만 저장됨

**해결 내용 (f1652ea)**:
```javascript
// ✅ localStorage 기반 다중 탭 대응 완료
const REDIRECT_LOCK_DURATION = 5000; // 5초 grace period

function isAlreadyRedirecting() {
  try {
    const redirectState = localStorage.getItem('auth_redirecting');
    if (!redirectState) return false;

    const { timestamp } = JSON.parse(redirectState);
    const now = Date.now();

    // 5초 이내에 다른 탭에서 리다이렉트 시작했으면 무시
    if (now - timestamp < REDIRECT_LOCK_DURATION) {
      return true;
    }

    // 5초 지났으면 만료된 것으로 간주하고 제거
    localStorage.removeItem('auth_redirecting');
    return false;
  } catch (error) {
    // localStorage 접근 실패 시 (incognito 모드 등) graceful degradation
    logger.warn('[Auth] localStorage 접근 실패, 이중 리다이렉트 방지 비활성화:', error);
    return false;
  }
}

function setRedirectingState() {
  try {
    localStorage.setItem('auth_redirecting', JSON.stringify({
      timestamp: Date.now(),
      tabId: crypto.randomUUID ? crypto.randomUUID() : Math.random().toString(36)
    }));
  } catch (error) {
    logger.warn('[Auth] localStorage 설정 실패:', error);
  }
}

// 사용 예시
if (isAlreadyRedirecting()) {
  logger.debug('[Auth] 다른 탭에서 이미 리다이렉트 진행 중, 현재 탭은 대기');
  return response;
}
setRedirectingState();
window.location.href = '/login?session_expired=true';
```

- `showSessionWarning()` 함수에서 `isRedirecting` 변수 참조 제거
