  ### 컨버팅 전략 제안

  1. 파편화된 자바스크립트 정리
      - 레거시 project-list.js 기능을 거대한 한 덩어리 대신 모듈 단위(데이터 소스, 필터, 테이블, 행 상세, 액션/잠금, inline 편집 등)로 기능 목록을 작성합
  니다.
      - 현재 Vite 구조도 ProjectListApp, ProjectTable, ProjectModal, ProjectFilters 등으로 쪼개져 있으니, 각 모듈이 커버해야 할 레거시 기능을 1:1로 매핑하
  세요.
  2. Data layer부터 복원
      - 기존 스크립트에서 사용하던 helper(safeParseCurrency, formatDate, updateCollectionStatus, lock 관련 API 등)를 src/js/utils/로 옮기고, 서버 API 사양을
  명확히 정리합니다.
      - /api/projects/update 같은 없는 엔드포인트 대신 실제 API(예: /api/projects, /api/projects/<code>)를 모듈화해 재사용 가능하게 만듭니다.
  3. UI 컴포넌트 단계적 마이그레이션
      - ProjectTable부터 상태 뱃지, 색상, 액션 버튼(UI/이벤트)을 옮기고, 행 확장을 위한 컴포넌트를 별도(RowDetails.js 등)로 분리해 도입합니다.
      - 필터 UI는 ProjectFilters에 company/manager/outstanding 등 모든 셀렉터를 바인딩하고, 레거시 필터 로직(예: 미수금 threshold, quick toggle)을 그대로 포
  팅하세요.
      - 모바일 카드/요약 카드/헤더 액션을 별도 컴포넌트로 나눠 연결합니다.
  4. 실시간 & 동시성 기능 이식
      - 레거시에서 사용하던 card_locked, card_unlocked, new_project_added, data_updated 소켓 이벤트를 새 구조에 구현합니다.
      - 잠금 상태를 관리하는 store(예: LockManager)와 inline 편집 시 사용한 helper를 Vite 쪽으로 옮기되, 기존 API (/api/field-lock/..., /api/update-project-
  inline)와 호환되게 만듭니다.
  5. 일괄 래핑 & 테스트
      - 기능이 모듈화되면, 레거시 스크립트를 제거하고 Vite 번들만 로드하도록 템플릿을 전환합니다. 동시에 회귀 테스트(Playwright/pytest)로 주요 플로우(필터,
  행 확장, 인라인 편집, 잠금, 소켓 이벤트 등)를 자동화하세요.
  6. CSS와 자산 정리
      - 새 CSS(dashboard/src/css)를 실제로 참조하도록 하고, 기존 project-list.css는 step별로 기능을 옮겨가며 정리합니다.
      - Row 상태/뱃지 색상, 카드 배경 등 기존 디자인 요소를 SCSS 컴포넌트로 재현하세요.
